# API reference

Everything Ovrin exports lives in one package at the module root. Provider implementations live in
their own modules, so the surface here is the whole contract: what you call, what you get back, and
what you implement if you are writing an adapter.

## Start here

If you are extracting a document for the first time, three pages cover it:

- [Extract[T]](/reference/extract) — the entry point
- [Client](/reference/client) — how you configure providers and limits
- [Result[T]](/reference/result) — what comes back, and how to read it

## The provider seams

Three small interfaces, and no vendor is privileged. Implement one to add a provider; the core never
learns its name.

| Page | Seam |
| --- | --- |
| [Model](/reference/model) | Turns document content plus a JSON schema into structured output. |
| [OCR](/reference/ocr) | Reads a rasterised page into words, lines, and positions. |
| [Renderer](/reference/renderer) | Rasterises a page for OCR or vision. Optional — most extractions never need one. |

## A note on stability

Ovrin is at **v1.0.0**, and this API is stable: nothing documented here will break without a v2. The
upstream repository records the public surface in `api/ovrin.txt`, which is now a compatibility contract
— removing an exported symbol or changing a signature is a release blocker, not a regeneration.
Additions still arrive in minor releases.

The promise covers the API only. It says nothing about accuracy, which is still unmeasured —
[release status](/community/release-status) sets out both.
